# Стенд подбора В2 — что зафиксировано (09.11.2026)

Эталон для переноса в «Закупай MVP»: файл `podbor-v2.html` (логика и дизайн). Переносить без изменения поведения и вида; всё, что ниже, — проверяемые правила из этого файла.

## 1. Сводка заявки
- Строка на позицию: №, наименование, кол-во, ед., статус, предложение, цена за ед. заявки, сумма.
- Статусы: «Выбрано», «Нужно решение», «Не найдено», «Поиск не запускался». Фильтр по статусу сверху, итог «Выбрано N из M · Итого».
- Предложение без выбора: лучший из подходящих по цене; если подходящих нет — ближайший по характеристикам с пометкой «точного нет, ближайший по характеристикам».
- Нажатие на строку раскрывает работу с позицией; кнопки «← Предыдущая», «Следующая →», «Следующая нерешённая →».

## 2. Разбор наименований на характеристики
- Порядок: правила по тексту (единицы и обозначения) → тип товара (первое существительное) → словарь слов (цвет, материал, покрытие, бренды, «Мой справочник») → остальное в «Прочие слова».
- Формы одного слова объединяются (основа слова и разница в одну букву у длинных слов); составные обозначения дробятся (М10×30 → резьба M10, длина 30 мм).
- Значения заявки отмечаются программой сами (✓, заливка без рамки), кроме тех, после которых не остаётся ни одного товара.

## 3. Отметки значений
- ✓ — обязательно; + — также, как аналог / замена; ✕ — исключить.
- В одной рубрике отмеченные значения — «или», разные рубрики — «и». ✕ убирает всегда.
- Колонка фильтров: у значения кнопки ✓ + ✕; у рубрики ✓ ✕ («указано» / «убрать»). Показано 5 значений, остальное под «Ещё N»; выбранные и значения заявки — сверху.
- В таблице значение — одна кнопка: быстрые нажатия 1 — ✓, 2 — +, 3 — ✕, 4 — снять; применяется через 0,35 с после последнего нажатия.
- Цвета: заливка — статус (✓ зелёный, + жёлтый, ✕ красный) кем бы ни поставлен; рамка — только у отметок оператора, того же цвета.

## 4. Таблица товаров
- Заголовок в две строки: «Данные заявки» (ед. изм., кол-во) | «Данные поставщика» (товар, ед. изм., кол-во, цена, цена за ед. заявки, сумма); группы разделены линиями, не заливкой.
- Ед. поставщика с содержимым единицы: «Штука (50 м)», «шт (5 шт)». Пересчёт: фасовка «(N шт)» / «, N шт.»; рулон «AxL м» при заявке в метрах.
- Одно упорядочивание всех товаров: сравнение с заявкой (и отметками) по всем характеристикам, кроме артикула, бренда и фасовки.
  - «Подходящие» — нет отличий от заявки; зелёные; «★ лучшая цена».
  - «Близкие по характеристикам» — 1–2 отличия от заявки, «совпадает X из Y», отличие «Поле: имеет вместо нужно» с красным ✕ (убрать этот товар) и чёрным ✕ (исключить значение у всех).
  - «Остальные — отличаются больше» — свёрнуты, с причиной.
  - Отличие в числе / размере весит больше, чем в слове.
- «Взять за основу» — эталон: его характеристики дополняют заявку там, где она молчит; параметры заявки важнее; эталон первым, видна строка «Эталон: … Убрать эталон».
- «Выбрать» — что идёт в счёт; отдельно от эталона.
- Под названием товара — его значения (кнопки с быстрыми нажатиями); «Фото» по нажатию (в приложении).

## 5. ИИ (на стенде через Claude страницы; в приложении — API)
- «Подобрать ИИ»: оценка каждого товара «подходит / аналог / не подходит» с обоснованием и отличиями; «★ выбор ИИ» только у «подходит». Числа и размеры заявки проверяются правилами: нет в названии → «подходит» понижается до «проверить». Правила понижают, не повышают.
- «Спросить ИИ»: свободный вопрос по позиции с контекстом (заявка, товары с ценами, отметки, оценки ИИ).
- «Разбор наименований: правила и ИИ» — сравнение; значение ИИ принимается, только если оно буквально есть в названии и рубрика из списка.

## 6. Известные недоработки В2 (исправлять при переносе осознанно)
- «3 в 1» читается как напряжение 3 В.
- Короткие цвета в женском роде («белая», «синяя») не распознаются словарём.
- Знаний о категориях нет: рубрики не зависят от категории (план: схемы рубрик по категориям + ИИ).
- Точность не измерена на реальной заявке; проверено на двух позициях.
